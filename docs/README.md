# Manuals

- [tld.md](tld.md): every public function, macro, type and variable of `tld.h`, module by
  module, with an alphabetical index.
- [tld_ai.md](tld_ai.md): the same for `tld_ai.h`.
- [tld_doc.md](tld_doc.md): the same for `tld_doc.h`.
- [design/tld_doc-prd.md](design/tld_doc-prd.md): the design of `tld_doc.h`.

The manuals are generated by `tools/tlddoc.c` from the comments in `tld.h`, `tld_ai.h` and
`tld_doc.h`; do not edit them. The same run writes the corpus block inside `tld_doc.h`
(one record per entry of `tld.md` and `tld_ai.md`, between its BEGIN CORPUS and END CORPUS
lines); do not edit that either. After changing a comment in `src/`, `tld_ai.h` or
`tld_doc.h`:

```sh
uv run python tools/amalgamate.py        # src/ -> tld.h
cmake --build build --target docs        # headers -> docs/*.md and the corpus in tld_doc.h
```

The test `docs-current` (`tlddoc --check`) fails while a manual or the corpus block is out
of date or a public symbol has no doc comment.

## Comment convention

- A doc comment is a comment block that ends on the line directly above a public
  declaration (function prototype, `#define`, typedef, struct or enum, extern variable),
  with no blank line in between.
- It documents that declaration and every declaration that follows it without a blank line
  or another comment in between, so a family of declarations (`TLD_MIN` and `TLD_MAX`,
  the `tld_json_get_*` getters, the `SORT_HEADER(type)` expansions) shares one comment.
  `#if`/`#ifdef`/`#ifndef`/`#else`/`#endif` lines do not interrupt a group.
- A comment at the end of a declaration's last line also counts as its doc comment.
- Each module header in `src/` starts with a module comment on its first line:
  `name: what the module is for`, 1 to 4 lines.
- The top comment of each header holds the title and overview (first paragraph,
  `file - what it is`) and sections headed by a line in capitals (`USAGE`, `ERRORS`, ...),
  their text indented beneath.
- Write what the code does, checked against the implementation: parameters, the return
  value (OK/FAIL, NULL, -1, ...), who frees what, thread-safety and edge cases. Usually 1 to
  4 lines. Plain text; lines indented further than the text around them, or aligned with
  runs of spaces, are shown verbatim (use this for examples).
- A code example is a block shown as C (a line ends in `;`, `{` or `}`, or is a
  `#define`). The tests `doc-examples`, `doc-examples-ai-mock` and `doc-examples-doc`
  compile and run each one as a program of its own (the `tld_ai.h` ones against a mock
  server), so it must
  declare what it uses and succeed when run; a blank line ends it, and output it pictures goes after
  `//`. `#define` lines and top-level invocations such as `AI_CHOICE(...)` are placed at
  file scope, the rest in a function with an `ERROR:` label; blocks with an `#include`
  are not compiled.
- Not documented (and not required): declarations inside `#if ..._IMPLEMENTATION`, `static`
  declarations, names starting with `_` or containing `__`, include guards, macros
  `#undef`'d in the same header, and forward declarations without a comment.
